# Календарь, задачи и пресеты

Этап 2: календарь, список задач и «лица» ассистента.

## API календаря: наносекунды

`POST /api/v1/calendars/events/create` ждёт `start_at`/`end_at` в
**наносекундах** (`epoch * 1e9`). Значения в миллисекундах создаются без
ошибки, но не попадают в `GET /events` — диапазон сравнивается с ns.

```bash
START=$(date -d 'tomorrow 15:00' +%s)000000000
curl -H "Authorization: Bearer $WEBUI_API_KEY" -H 'Content-Type: application/json' \
  -d "{\"calendar_id\":\"<id>\",\"title\":\"Встреча\",\"start_at\":$START}" \
  http://<pi>/api/v1/calendars/events/create
```

Брифинг (`proactive`) читает `start_at` и делит на 1e9 — см. `proactive/app.py`.

## Календарь

Используется **встроенный календарь Open WebUI** (`ENABLE_CALENDAR=true`
по умолчанию, раздел «Календарь» в боковом меню).

Возможности:
- личные календари и события, доступ по грантам (календарь можно открыть
  другому пользователю);
- события участвуют в чате: ассистент видит их через инструменты;
- хранится в PostgreSQL вместе с чатами — один бэкап на всё.

### Про CalDAV

В Open WebUI v0.13.3 **нет** CalDAV/ICS: встроенный календарь не
синхронизируется с внешними CalDAV-серверами. Поэтому:

- события создаются в вебе и через ассистента (MCP-инструменты, этап 4);
- Vikunja отдаёт **задачи** по CalDAV (`http://<pi>:8081/dav/`) — их можно
  подключить к календарю телефона;
- отдельный Radicale и двусторонняя синхронизация событий — этап 4,
  см. `docs/decisions.md` (ADR-016).

## Задачи (Vikunja)

- Адрес: `http://<ip-pi>:8081` (порт публикует nginx, только LAN).
- Регистрация закрыта (`VIKUNJA_SERVICE_ENABLEREGISTRATION=false`).
- Пользователь создаётся скриптом: `make vikunja-admin`.
  Пароль генерируется и кладётся в `${DATA_ROOT}/secrets/vikunja-admin.txt`
  (права 600). Смените пароль в интерфейсе и удалите файл.
- База — отдельная БД `vikunja` в том же PostgreSQL (экономия ОЗУ).
- CalDAV включён: в клиенте календаря укажите
  `http://<ip-pi>:8081/dav/` и логин/пароль Vikunja.
- Vikunja 2.x: instance-admin — платная функция, для одного пользователя
  не нужна. Дополнительных пользователей создаёт CLI
  (`docker compose exec vikunja /app/vikunja/vikunja user create ...`).

### Зачем отдельный порт

Vikunja не поддерживает работу из подкаталога: API и фронтенд живут в корне.
Поэтому nginx слушает `:8081` и проксирует всё в контейнер. Когда появится
домен — заменить на `server_name tasks.<домен>` с TLS (см.
`nginx/conf.d/20-tasks.conf`).

## Пресеты-«лица»

Файлы в `presets/*.md`: системный промпт, температура, capabilities.
Импорт создаёт модели в Workspace → Models:

```bash
WEBUI_API_KEY=sk-... ./scripts/import-presets.sh --base-model deepseek-chat
# или только собрать presets/models.json:
./scripts/import-presets.sh --dry-run
```

Повторный импорт обновляет пресеты по `id`.

| Пресет | Для чего |
|---|---|
| Secretary | секретарь: календарь, задачи, заметки, напоминания |
| Omni | универсальный ассистент со всеми инструментами |
| Archivist | Obsidian-вольт: поиск и запись, экономия контекста |
| Coder | код, git, GitHub, файлы, shell |
| Private | без памяти, истории и инструментов |

## Режимы чатов

| Режим | Как включить | Что происходит |
|---|---|---|
| Обычный | просто чат | история и память сохраняются |
| Временный | меню чата → Temporary Chat | чат не пишется в БД |
| Приватный | Temporary Chat + пресет Private | без памяти, знаний, инструментов |
| Ограниченная память | пресет + отключённая память/RAG | история есть, память не пополняется |

Приватный режим — это комбинация: Open WebUI не сохраняет временный чат,
а пресет Private запрещает обращаться к памяти и инструментам. На уровне
инфраструктуры гарантия — временный чат; пресет — дисциплина модели.

## Проверка

```bash
make smoke
```

Smoke-тест проверяет:
- календарь: `/api/v1/calendars/` отвечает 401 без токена (эндпоинт жив);
- Vikunja: `:8081/healthz` и `/api/v1/info` отвечают 200;
- схема `vikunja` создана в PostgreSQL.

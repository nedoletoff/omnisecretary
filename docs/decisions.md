# Принятые решения

## ADR-001. Образы фиксированы
- **Решение:** фиксировать теги образов в `docker-compose.yml`.
- **Почему:** воспроизводимость и предсказуемые обновления на Pi.
- **Текущее:** open-webui v0.13.3, postgres 16+pgvector, qdrant v1.19.2,
  redis 8.8.4-alpine, nginx 1.30.6-alpine, vikunja 2.8.0 и др.
- **Обновление:** отдельный коммит с правкой тегов, после проверки changelog.

## ADR-002. PostgreSQL вместо SQLite
- **Решение:** PostgreSQL 16 с расширением `vector`.
- **Почему:** многопользовательский режим, конкурентный доступ, миграции,
  единая СУБД для ядра и Vikunja.

## ADR-003. Qdrant для векторной памяти
- **Решение:** Qdrant.
- **Почему:** в v0.13.3 в `VECTOR_DB` нет `pgvector`; стабильный API,
  отдельный контейнер с лимитом памяти. Версия прижата к совместимой с
  клиентом Open WebUI.

## ADR-004. Redis включён
- **Решение:** Redis включён.
- **Почему:** кэширование и снижение повторных вычислений при скромных
  ресурсах.

## ADR-005. Nginx как reverse proxy
- **Решение:** отдельный контейнер nginx.
- **Почему:** единая точка входа, WebSocket/SSE, TLS, маршрутизация
  (портал, вольт, домены).

## ADR-006. DATA_ROOT по умолчанию на SD, переносим на диск
- **Решение:** по умолчанию `/srv/omnisecretary`, перенос на `/mnt/data`.
- **Почему:** сразу разворачивается без внешнего диска; Docker data-root и
  тома выносятся при подключении диска.

## ADR-007. Облачные LLM, без локальных моделей
- **Решение:** локальные LLM на Pi не запускать.
- **Почему:** 4 ГБ ОЗУ и CPU Pi недостаточны. Допускаются лёгкие сервисы
  (STT/TTS, эмбеддинги), но не генеративные LLM.

## ADR-008. Календарь и задачи
- **Решение:** встроенный календарь Open WebUI (события) + Vikunja (задачи,
  CalDAV). Vikunja использует отдельную схему/БД в том же PostgreSQL.
- **Почему:** экономия памяти, один сервер БД. CalDAV-синхронизация
  событий Open WebUI отсутствует в v0.13.3 (см. ADR-016).

## ADR-009. Секреты только в env/файлах
- **Решение:** `.env` и `secrets/` (600), `.env.example` без значений.
- **Почему:** предотвращение утечек в git, логах, чатах.

## ADR-010. Регистрация и Telegram
- **Решение:** публичная регистрация Open WebUI выключена; регистрация —
  по токену через портал. Telegram — allowlist/код подтверждения.
- **Почему:** приватный сервис.

## ADR-011. ARM64 обязателен
- **Решение:** проверять `linux/arm64` у образов.
- **Почему:** целевая платформа — Raspberry Pi 4.

## ADR-012. Бюджет памяти
- **Решение:** лимиты памяти у сервисов, где возможно; профили `mem_limit`.
- **Почему:** OOM на 4 ГБ. (Фактически применяются при включённом
  memory-cgroup; rootless/ядро настроены.)

## ADR-013. Порядок разработки
- **Решение:** этапы по плану, каждый — с проверкой, docs и коммитом.
- **Почему:** управляемость и воспроизводимость.

## ADR-014. Голос
- **Решение:** STT — sherpa-onnx с моделью Vosk small-ru (ONNX); TTS —
  Silero v4_ru (основной), Piper — альтернатива. Отдельные контейнеры,
  OpenAI-совместимые эндпоинты.
- **Почему:** русская речь, приемлемая память, изоляция от ядра. Streaming
  Vosk не влезает в 4 ГБ.

## ADR-015. Vikunja — отдельная БД в том же PostgreSQL
- **Решение:** база/схема `vikunja` в существующем postgres, без второго
  сервера.
- **Почему:** ~150 МБ экономии ОЗУ. Init идемпотентен.

## ADR-016. CalDAV для событий Open WebUI — отложен
- **Решение:** события — встроенный календарь Open WebUI; задачи —
  Vikunja/CalDAV. Мост событий — позже.
- **Почему:** в v0.13.3 нет CalDAV-синхронизации событий.

## ADR-017. MCP — внешние серверы
- **Решение:** MCP-серверы как отдельные контейнеры (streamable HTTP).
- **Почему:** изоляция, лимиты, независимые перезапуски, минимум прав.

## ADR-018. memory-cgroup и лимиты
- **Решение:** включить memory-cgroup в ядре; использовать лимиты контейнеров.
- **Почему:** защита от OOM на 4 ГБ. После настройки лимиты применяются.

## ADR-019. Docker rootless
- **Решение:** перейти на rootless Docker.
- **Статус:** ✅ выполнено (user daemon, bind-монты, subuid, сертификаты
  адаптированы, rootful отключён, откат сохранён).
- **Почему:** уменьшение поверхности атаки; без `sudo` для docker.

## ADR-020. Портал регистрации и аккаунта
- **Решение:** отдельный сервис портала для регистрации по токену, входа
  по логину, личных настроек и мобильного API.
- **Почему:** в Open WebUI v0.13.3 нет нужного UX без почты; единая точка
  для `/api/m/*` и персональных вольтов.

## ADR-021. VPN-прокси для исходящих соединений
- **Решение:** Xray-прокси, выбор серверов, маршрутизация только нужных
  сервисов (Telegram, proactive, llm-gateway при необходимости).
- **Почему:** блокировки; локальные сервисы и обновления — напрямую.

## ADR-022. Android-клиент
- **Решение:** нативное приложение на Jetpack Compose, интеграция с
  Open WebUI API и `/api/m/*`, сборка в GitHub Actions, раздача APK/Releases.
- **Почему:** нужен полноценный мобильный ассистент (виджет, плитка, share,
  интенты, биометрия, голос, оффлайн-очереди), чего PWA не покрывает.

## ADR-023. Уведомления: Telegram, локальные, ntfy
- **Решение:** Telegram и уведомления приложения — раздельно; локальные
  напоминания в приложении; ntfy — опциональный self-hosted push.
- **Почему:** разные каналы и сценарии, без обязательной зависимости от FCM.

## ADR-024. Персональные Obsidian-вольты и права по папкам
- **Решение:** у каждого пользователя свой git-репозиторий вольта, PAT и
  настраиваемые права (read/list/search/create/append/update/delete) по
  префиксам папок. Проверка — **программно на сервере** при каждом действии;
  хранение изолировано (`vaults/<user_id>`), токен шифруется.
- **Почему:** приватность, контроль пользователя, защита от обхода
  ограничений промптом/моделью.

## ADR-025. Темы Android: Gruvbox и Material You
- **Решение:** две независимые палитры — Gruvbox и Material You (динамические
  цвета системы, Android 12+). Семантические цвета (`AppColors`) задаются
  темой целиком, без смешивания.
- **Почему:** фирменный стиль и системная интеграция, без цветовых конфликтов.

## ADR-026. Действия на устройстве
- **Решение:** распознавание явных команд (таймер, будильник, открыть
  приложение, поиск, маршрут, звонок) и выполнение через системные интенты
  Android; панель быстрых действий.
- **Почему:** сценарии ассистента «как Gemini» без лишних привилегий.

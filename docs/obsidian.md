# Obsidian-вольт

## Модели доступа

### 1. Персональный вольт пользователя (основной, в приложении и `/api/m/*`)
Каждый пользователь может подключить **свой** приватный git-репозиторий
Obsidian и свой GitHub-токен.

- Настройка: в Android-приложении **Заметки → Obsidian** (или через
  API портала `GET/POST /api/m/vault/config`).
- Параметры: URL репозитория, ветка, GitHub PAT (fine-grained,
  Contents: read/write на этот репозиторий), флаг push.
- Хранение: клон в `${DATA_ROOT}/vaults/<user_id>`, индекс FTS5 —
  `${DATA_ROOT}/vaults/<user_id>.index`. Токен хранится зашифрованным
  в БД портала, права доступа к файлам ограничены.
- Изоляция: у каждого пользователя свой вольт, индекс и права; данные
  не пересекаются.

### 2. Общий вольт владельца (серверный, `/vault/` и MCP)
Существующий вольт владельца, подключённый через форму
`https://<домен>/vault/` (`vault-manager`), используется серверными
инструментами (MCP `mcp-vault`, брифинг/индексация по текущей
конфигурации).

- Репозиторий: `nedoletoff/obsidian_vault` (текущая настройка).
- Статус: `/vault/status` (Basic Auth: `owner` / `secrets/vault-admin.txt`).
- Владелец может также подключить этот же репозиторий как
  **персональный** в приложении, чтобы пользоваться правами по папкам.

> MCP-инструменты вольта в веб-чате пока ориентированы на общий вольт и
> требуют доработки для per-user контекста. В приложении и эндпоинтах
> `/api/m/vault/*` используется персональный вольт с проверкой прав.

## Права доступа по папкам (программное ограничение)

Для персонального вольта пользователь задаёт правила для путей/префиксов:

| Право | Действие |
|---|---|
| `read` | чтение содержимого заметки |
| `list` | отображение в списке файлов |
| `search` | попадание в результаты поиска |
| `create` | создание новой заметки |
| `append` | дополнение существующей |
| `update` | изменение содержимого |
| `delete` | удаление |

**Гарантии:**
- Проверка выполняется **на сервере при каждом действии** (API/портал).
  Модель или клиент не могут обойти ограничения промптом.
- Применяется самое точное (длинное) совпадающее правило по префиксу пути.
- Если разрешающего правила нет — действие запрещено.
- По умолчанию: чтение/список/поиск всего; создание/дополнение/изменение
  в `AI/`; удаление выключено. Пользователь может запретить отдельные
  папки (например, `Личное/`) или сузить запись.

Настройка: **Заметки → Obsidian → Права по папкам** в приложении или
`GET/POST /api/m/vault/permissions`.

## Структура (рекомендация)

```
AI/
  Inbox/      заметки, созданные ассистентом
  Daily/      выжимки и итоги
  Projects/   проектные заметки
  Archive/    прочитанное/обработанное
```

Правила можно настроить так, чтобы запись была разрешена только в `AI/`
или отдельных подпапках.

## Синхронизация и запись

- Каждая запись — по **прямой команде** пользователя (в приложении:
  действие «Заметка в Obsidian», `/api/m/note` или операции вольта).
- Запись в персональном вольте: создаётся/обновляется файл в разрешённой
  папке, выполняется git commit; push — если включён и разрешён.
- Фоновых и «инициативных» записей нет.
- Конфликты при push: выполняется `pull --rebase` и повтор push (для
  серверного вольта); при проблемах — ошибка в статусе/ответе API.
- Ручная синхронизация: `POST /api/m/vault/sync` (приложение) или
  `/vault/sync` (серверный вольт, владелец).

## Экономия токенов и контекста

- Ассистент **не читает вольт целиком**. Сначала поиск (FTS5-индекс),
  затем чтение 1–2 конкретных заметок.
- Результаты поиска содержат путь и сниппет/цитату — модель опирается на
  найденные фрагменты.
- Индекс перестраивается после синхронизации.

## Безопасность

- GitHub PAT — только в защищённом хранилище (зашифрован в БД портала для
  персональных вольтов / `secrets/` для серверного), права 600, не в git.
- Для PAT: fine-grained, доступ только к нужному репозиторию,
  Contents: read/write, срок и ротация — по политике владельца.
- Репозиторий — приватный. Доступ к персональному вольту имеет только
  владелец аккаунта; серверные эндпоинты требуют авторизацию.
- Ассистент читает и пишет **только** то, что разрешено правилами папок
  и запрошено явно.

## Ограничения

- Персональные вольты — один репозиторий на пользователя в текущей
  реализации приложения/портала.
- MCP-инструменты в чате не полностью per-user (см. выше).
- Большие бинарные вложения в вольте не оптимизированы для индексации.
- При недоступности GitHub push может не выполниться — изменения остаются
  в локальном клоне на сервере до успешной синхронизации.

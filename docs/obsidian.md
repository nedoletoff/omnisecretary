# Obsidian-вольт: как это работает

Статус: **реализовано** (этап 4). Требования зафиксированы пользователем
2026-11-09, уточнены 2026-11-10 (подключение через интерфейс, доступ только
владельцу, отдельные папки для ИИ, экономия контекста).

## Что сделано

```
Open WebUI ──(MCP, http)──▶ mcp-vault ──▶ ${DATA_ROOT}/vault (git clone)
     │                          │                    │
     │                          └── FTS5-индекс (${DATA_ROOT}/vault-index)
     │
     └──(браузер, /vault/)──▶ vault-manager ── clone / pull / push ──▶ origin
                                  │
                                  └── токен: ${DATA_ROOT}/secrets/vault-git-token (600)
```

| Сервис | Контейнер | Роль | Память |
|---|---|---|---|
| `vault-manager` | `omni-vault-manager` | веб-форма подключения и синхронизации, Basic Auth | 96 МБ |
| `mcp-vault` | `omni-mcp-vault` | MCP-инструменты вольта, git-коммиты | 128 МБ |

Оба — в сети `backend`, порты наружу не публикуются. `vault-manager`
доступен только через nginx по пути `/vault/` (LAN).

## Подключение (через интерфейс, без правки файлов)

1. Открыть `http://<ip-pi>/vault/`.
2. Логин — `VAULT_ADMIN_USER` (по умолчанию `owner`), пароль — из `.env`
   (`VAULT_ADMIN_PASSWORD`, сгенерирован bootstrap). Посмотреть:
   `grep VAULT_ADMIN_PASSWORD .env` на Pi.
3. Ввести URL приватного репозитория (`https://...git`), ветку и PAT.
4. «Подключить» — сервис клонирует вольт в `${DATA_ROOT}/vault`.

Токен сохраняется в `${DATA_ROOT}/secrets/vault-git-token` с правами 600.
В `.git/config` и в URL репозитория он не попадает: git получает его через
`http.extraheader` на время команды. Повторная отправка формы без токена
сохраняет прежний токен.

## Инструменты ИИ

| Инструмент | Что делает | Токены |
|---|---|---|
| `vault_status()` | ветка, число незакоммиченных файлов, 5 последних коммитов | мало |
| `vault_search(q, limit=5, folder?)` | FTS5-поиск → путь + сниппет 14 слов | мало |
| `vault_read(path, offset, max_chars=4000)` | чтение одной заметки с обрезкой | по требованию |
| `vault_list(folder?, limit=100)` | только пути, без содержимого | мало |
| `vault_create(path, content, title?)` | создать заметку в `AI/` + коммит | — |
| `vault_append(path, content, heading?)` | дополнить заметку + коммит | — |
| `vault_replace(path, old, new)` | точная замена первого вхождения + коммит | — |
| `vault_sync()` | `pull --rebase` и отправка локальных коммитов | — |

Индекс инкрементальный: переиндексируются только файлы с изменившимся
mtime/размером. Весь вольт в контекст не попадает никогда.

## Правила записи

- Запись разрешена **только** в `AI/` (`VAULT_WRITE_PREFIX`). Попытка
  записать в чужую папку возвращает ошибку, файл не создаётся.
- Создание не перезаписывает существующий файл (для этого `vault_append`
  или `vault_replace`).
- Каждая операция записи — отдельный git-коммит
  (`ai: создать AI/Notes/...`), push выполняется в фоне с задержкой 2 с,
  чтобы серия записей ушла одним push.
- Если сети нет — коммит остаётся локально; `make backup` и `vault_sync()`
  досылают его позже.

Структура, которую создаёт ИИ:

```
AI/
├── Inbox/        быстрые захваты («запиши, что…»)
├── Notes/        структурированные заметки
├── Summaries/    выжимки диалогов
├── Daily/        утренние брифинги
└── Archive/      устаревшее
```

## Доступ к папкам и правило прямого запроса

- Чтение и поиск доступны по всему вольту, но **только по явному вызову**
  инструмента: ассистент не загружает вольт в контекст и не сканирует его
  без запроса пользователя.
- Запись — **только по прямой просьбе** («запиши…», «дополни…»), только в
  `AI/`, с отдельным коммитом на операцию. Фоновых и «инициативных»
  записей нет.
- Изменение существующих заметок вне `AI/` запрещено на сервере, а не в
  промпте: обход через формулировку невозможен.
- У каждого пользователя будет свой вольт (отдельный репозиторий и токен).
  Сейчас вольт один — владельца; MCP-сервер не имеет доступа к вольтам
  других пользователей, потому что их ещё нет.

## Доступ только владельцу

- MCP-сервер зарегистрирован в Open WebUI **без `access_grants`** — такие
  tool servers видит только администратор (владелец).
- Инструменты вольта включены в пресеты `Archivist` и `Omni`; остальные
  пресеты их не получают (`presets/models.json` → `toolIds`).
- Контейнеры не публикуют порты и не имеют docker.sock.
- Токен не показывается в интерфейсе и не пишется в логи.

## Проверка

```bash
make smoke                       # 44 проверки, включая MCP и /vault/
curl -u owner:<пароль> http://<ip>/vault/status
```

Ручной сценарий: спросить в чате с пресетом Archivist «найди в вольте
заметки про <тема>» → ассистент вызывает `vault_search`, затем `vault_read`.
Затем «запиши в AI/Inbox/идеи.md: ...» → появляется коммит
`git -C /srv/omnisecretary/vault log --oneline -1`.

## Ограничения и допущения

- Конфликты при `pull --rebase` разрешаются `--autostash`; при реальном
  конфликте содержимого операция завершится ошибкой — владелец увидит это
  в `/vault/` (dirty files) и разрешит вручную. Автоматическое откладывание
  в `AI/Conflicts/` не реализовано (см. ADR-025).
- Большие бинарные файлы вольта не индексируются — только `*.md`.
- Просмотр вольта внутри Open WebUI не делается: для этого есть Obsidian и
  сам `/vault/`.
- Мультипользовательские вольты — в плане: один контейнер `mcp-vault` сейчас
  обслуживает один репозиторий (владельца).

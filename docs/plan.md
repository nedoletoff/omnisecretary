# План реализации

Принцип: каждый этап заканчивается работающей, проверяемой системой.
Переход к следующему — только после зелёного `make smoke` и коммита.

## Этап 1 — Ядро (✅ реализовано и запущено на Pi)

**Цель:** Open WebUI доступен по HTTP через nginx, данные в PostgreSQL,
память в Qdrant, всё поднято одной командой.

Файлы:
- `docker-compose.yml` — nginx, open-webui, postgres, qdrant, redis; healthchecks, лимиты.
- `nginx/` — reverse proxy, WebSocket, SSE, ACME-webroot, HTTPS-заготовка.
- `.env.example`, `.gitignore`.
- `scripts/bootstrap-pi.sh` + `scripts/lib/common.sh` — установка и настройка.
- `scripts/smoke-test.sh`, `scripts/backup.sh`, `scripts/update.sh`.
- `Makefile`.
- `docs/*`, `README.md`, `AGENTS.md`.

Критерии приёмки:
- `make up` поднимает 5 контейнеров, все healthy.
- `make smoke` — 0 ошибок.
- Веб-интерфейс открывается, первый пользователь создаётся, чат с облачной LLM работает.
- Перезагрузка Pi → стек поднимается сам (`restart: unless-stopped`).
- `make backup` создаёт дамп Postgres и снапшоты Qdrant.

## Этап 2 — Календарь, задачи, пресеты (✅ реализовано)

**Цель:** ассистент умеет вести календарь и задачи; есть «лица» под задачи.

Файлы:
- `docker-compose.yml` — `vikunja` + одноразовый `db-init` (отдельная БД
  `vikunja` в общем PostgreSQL); `nginx/conf.d/20-tasks.conf` (порт 8081).
- `presets/secretary.md`, `omni.md`, `archivist.md`, `coder.md`, `private.md`.
- `scripts/import-presets.sh` / `import-presets.py` — импорт через API.
- `scripts/init-vikunja.sh` — создание пользователя Vikunja (идемпотентно).
- `docs/calendar-tasks.md` — календарь, задачи, пресеты, режимы чатов.

Критерии приёмки:
- Встроенный календарь Open WebUI доступен, эндпоинт `/api/v1/calendars/` жив.
- Vikunja доступна через nginx на `:8081`, регистрация закрыта, вход по логину.
- Задачи Vikunja отдаются по CalDAV (`/dav/`).
- Пресеты импортируются одной командой и видны в списке моделей.
- Приватный пресет не обращается к памяти и инструментам.

Отклонение от исходного плана: Radicale не ставим — CalDAV-событий в
Open WebUI v0.13.3 нет, а Vikunja уже отдаёт задачи по CalDAV.
См. ADR-016 в `docs/decisions.md`.

## Этап 3 — Telegram и многопользовательский режим (✅ реализовано)

**Цель:** те же чаты из Telegram; доступ только по allowlist.

Файлы:
- `bot/telegram_bot.py` — сервис на стандартной библиотеке (без зависимостей),
  работает через API Open WebUI, пишет в те же чаты (`chat_id`), long polling
  (без публичного webhook).
- `docker-compose.yml` — сервис `telegram-bot` (профиль `telegram`, 96 МБ).
- `docs/telegram.md` — allowlist, отключение регистрации, роли, изоляция.

Реализовано:
- у каждого Telegram ID свой аккаунт Open WebUI — истории не пересекаются;
- владелец (`TELEGRAM_OWNER_ID`) ходит под своим аккаунтом: чаты общие с вебом;
- `/private` — запрос без `chat_id`, ничего не сохраняется и не читается;
- посторонние ID игнорируются, попытка пишется в лог;
- модели открыты всем пользователям на чтение (иначе в v0.13 пресет
  виден только владельцу), шаринг чатов и заметок выключен.

Критерии приёмки:
- Сообщение из Telegram появляется в веб-интерфейсе в том же чате и наоборот.
- Посторонний Telegram ID получает отказ, в лог пишется попытка.
- Публичная регистрация в вебе закрыта, новых пользователей создаёт админ.

## Этап 4 — MCP-инструменты и Obsidian (✅ реализовано)

**Цель:** ассистент пишет в Obsidian, работает с GitHub, файлами, песочницей.

Файлы:
- `mcp/Dockerfile`, `mcp/requirements.txt` — общий образ для всех MCP-серверов.
- `mcp/servers/vault.py` — Obsidian: FTS5-поиск, чтение, запись в `AI/`, git.
- `mcp/servers/files.py`, `github.py`, `vikunja.py`, `shell.py` — остальные серверы.
- `mcp/vault_manager/app.py` — веб-форма `/vault/`: clone / pull / push, Basic Auth.
- `scripts/init-mcp.py` — регистрация серверов и выдача инструментов пресетам.
- `nginx/conf.d/00-default.conf` — маршрут `/vault/`.
- `docs/mcp.md`, `docs/obsidian.md`.

Реализовано:
- 5 MCP-серверов в сети `backend`, без публикации портов, у каждого `mem_limit`;
- tool servers без `access_grants` → видны только владельцу;
- пресеты получают инструменты по роли, Private — ничего;
- вольт подключается через `/vault/` (URL + PAT), токен в `secrets/`, не в git;
- запись только в `AI/`, каждая операция — git-коммит с фоновым push;
- песочница без docker.sock и host-сети, allowlist команд, запрет метасимволов.

Критерии приёмки:
- «Запиши в Obsidian, что…» → заметка в `AI/Inbox` + git-коммит + push.
- «Найди в заметках…» → точный ответ со ссылкой на файл, без загрузки вольта целиком.
- Вольт подключается через интерфейс (URL + PAT); токен не попадает в git и чат.
- Вольт доступен только владельцу; второй пользователь инструментов вольта не видит.
- GitHub: чтение приватного репозитория, создание issue/PR по команде.
- Песочница: код выполняется изолированно, `rm/sudo/apt` отклоняются.

Отклонение: отдельный SSH/Computer Use MCP не разворачивается — доступ к
shell хоста не автоматизирован (ADR-026). Вместо него — песочница.

## Этап 5 — Голос

**Цель:** русский STT и TTS.

Файлы:
- `docker-compose.yml` — `vosk-stt` (vosk-model-small-streaming-ru), `silero-tts`.
- `nginx/conf.d/` — маршруты `/stt`, `/tts` (или прямое подключение Open WebUI).
- `docs/voice.md`.

Критерии приёмки:
- Голосовой ввод в вебе распознаёт русскую речь.
- Озвучка ответов работает, задержка приемлема на Pi.
- Память: контейнеры голоса ≤ 400 МБ суммарно.

## Этап 6 — Проактивность и мобильный доступ

**Цель:** утренний брифинг, напоминания, PWA.

Файлы:
- `scripts/briefing.py` (или сервис `briefing/`) — погода, календарь, задачи, заметки → Telegram.
- `docker-compose.yml` — сервис `scheduler` (cron-подобный).
- `docs/pwa.md` — установка PWA, быстрые действия.

Критерии приёмки:
- Брифинг приходит в Telegram в заданное время.
- Напоминание срабатывает по расписанию.
- PWA устанавливается на телефон, открывает нужный пресет в 1–2 нажатия.

## Этап 7 — Стабилизация

- Фиксация версий Open WebUI после обкатки.
- Прогон `docs/acceptance.md` целиком.
- Инструкция переноса `${DATA_ROOT}` на внешний диск.
- Автоматизация бэкапов и мониторинга (healthcheck → Telegram-алерт).

## Риски

| Риск | Митигация |
|---|---|
| 4 ГБ ОЗУ не хватает | лимиты памяти, swap 2 ГБ, отказ от локальных моделей |
| SD-карта изнашивается | логи ограничены, data-root на внешний диск, бэкапы |
| Open WebUI меняет API | фиксированные теги, smoke-тест после обновления |
| Telegram-бот и веб расходятся | бот пишет через API в те же `chat_id` |
| MCP-инструменты опасны | allowlist, подтверждения, минимальные PAT |
| Публичный доступ | Cloudflare Tunnel или HTTPS + закрытая регистрация |

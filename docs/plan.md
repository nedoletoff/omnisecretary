# План реализации

Принцип: каждый этап заканчивается работающей, проверяемой системой.
Переход к следующему — только после зелёного `make smoke` и коммита.

## Этап 1 — Ядро (✅ реализовано, ждёт запуска на Pi)

**Цель:** Open WebUI доступен по HTTP через nginx, данные в PostgreSQL,
память в Qdrant, всё поднято одной командой.

Файлы:
- `docker-compose.yml` — nginx, open-webui, postgres, qdrant, redis; healthchecks, лимиты.
- `nginx/` — reverse proxy, WebSocket, SSE, ACME-webroot, HTTPS-заготовка.
- `.env.example`, `.gitignore`.
- `scripts/bootstrap-pi.sh` + `scripts/lib/common.sh` — установка и настройка.
- `scripts/smoke-test.sh`, `scripts/backup.sh`, `scripts/update.sh`.
- `Makefile`.
- `docs/*`, `README.md`, `AGENTS.md`.

Критерии приёмки:
- `make up` поднимает 5 контейнеров, все healthy.
- `make smoke` — 0 ошибок.
- Веб-интерфейс открывается, первый пользователь создаётся, чат с облачной LLM работает.
- Перезагрузка Pi → стек поднимается сам (`restart: unless-stopped`).
- `make backup` создаёт дамп Postgres и снапшоты Qdrant.

## Этап 2 — Календарь, задачи, пресеты (⏳ следующий, приоритет пользователя)

**Цель:** ассистент умеет вести календарь и задачи; есть «лица» под задачи.

Файлы:
- `docker-compose.yml` — сервисы `radicale` (CalDAV) и `vikunja` (+ его БД).
- `presets/secretary.md`, `omni.md`, `archivist.md`, `coder.md`, `private.md`.
- `scripts/import-presets.sh` — загрузка пресетов в Open WebUI через API.
- `docs/calendar-tasks.md` — подключение CalDAV в Open WebUI и клиентах.

Критерии приёмки:
- В Open WebUI встроенный календарь показывает события из Radicale.
- Vikunja доступна через nginx по пути `/tasks/` (или отдельному порту), вход по приглашению.
- Пресеты видны в списке моделей/пресетов, каждый со своим промптом и моделью.
- Приватный пресет не обращается к памяти.

## Этап 3 — Telegram и многопользовательский режим

**Цель:** те же чаты из Telegram; доступ только по allowlist.

Файлы:
- `bot/` — сервис на python-telegram-bot, работает через API Open WebUI,
  пишет в те же чаты (`chat_id`), long polling (без публичного webhook).
- `docker-compose.yml` — сервис `telegram-bot`.
- `docs/telegram.md` — allowlist, отключение регистрации, роли.

Критерии приёмки:
- Сообщение из Telegram появляется в веб-интерфейсе в том же чате и наоборот.
- Посторонний Telegram ID получает отказ, в лог пишется попытка.
- Публичная регистрация в вебе закрыта, новых пользователей создаёт админ.

## Этап 4 — MCP-инструменты и Obsidian

**Цель:** ассистент пишет в Obsidian, работает с GitHub, файлами, SSH, календарём.

Файлы:
- `mcp/` — compose-фрагменты/конфиги: obsidian, github, filesystem, ssh, caldav, vikunja.
- `vault-sync/` — подключение вольта через веб-форму (repo URL + PAT), клон, pull/commit/push.
- `obsidian-mcp/` — MCP-инструменты поиска/чтения/записи с FTS5-индексом.
- `scripts/init-vault.sh` — структура папок `AI/*`, правила записи.
- `docs/mcp.md` — подключение MCP к Open WebUI, матрица прав.
- `docs/obsidian.md` — требования и проект (уже зафиксированы).
- `docs/security.md` — раздел про подтверждения опасных операций.

Критерии приёмки:
- «Запиши в Obsidian, что…» → заметка в `AI/Inbox` + git-коммит + push.
- «Найди в заметках…» → точный ответ со ссылкой на файл, без загрузки вольта целиком.
- Вольт подключается через интерфейс (URL + PAT); токен не попадает в git и чат.
- Вольт доступен только владельцу; второй пользователь инструментов вольта не видит.
- GitHub: чтение приватного репозитория, создание issue/PR по команде.
- SSH/Computer Use: выполнение команды только после подтверждения.

## Этап 5 — Голос

**Цель:** русский STT и TTS.

Файлы:
- `docker-compose.yml` — `vosk-stt` (vosk-model-small-streaming-ru), `silero-tts`.
- `nginx/conf.d/` — маршруты `/stt`, `/tts` (или прямое подключение Open WebUI).
- `docs/voice.md`.

Критерии приёмки:
- Голосовой ввод в вебе распознаёт русскую речь.
- Озвучка ответов работает, задержка приемлема на Pi.
- Память: контейнеры голоса ≤ 400 МБ суммарно.

## Этап 6 — Проактивность и мобильный доступ

**Цель:** утренний брифинг, напоминания, PWA.

Файлы:
- `scripts/briefing.py` (или сервис `briefing/`) — погода, календарь, задачи, заметки → Telegram.
- `docker-compose.yml` — сервис `scheduler` (cron-подобный).
- `docs/pwa.md` — установка PWA, быстрые действия.

Критерии приёмки:
- Брифинг приходит в Telegram в заданное время.
- Напоминание срабатывает по расписанию.
- PWA устанавливается на телефон, открывает нужный пресет в 1–2 нажатия.

## Этап 7 — Стабилизация

- Фиксация версий Open WebUI после обкатки.
- Прогон `docs/acceptance.md` целиком.
- Инструкция переноса `${DATA_ROOT}` на внешний диск.
- Автоматизация бэкапов и мониторинга (healthcheck → Telegram-алерт).

## Риски

| Риск | Митигация |
|---|---|
| 4 ГБ ОЗУ не хватает | лимиты памяти, swap 2 ГБ, отказ от локальных моделей |
| SD-карта изнашивается | логи ограничены, data-root на внешний диск, бэкапы |
| Open WebUI меняет API | фиксированные теги, smoke-тест после обновления |
| Telegram-бот и веб расходятся | бот пишет через API в те же `chat_id` |
| MCP-инструменты опасны | allowlist, подтверждения, минимальные PAT |
| Публичный доступ | Cloudflare Tunnel или HTTPS + закрытая регистрация |

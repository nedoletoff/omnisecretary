# Портал: регистрация, вход, личные настройки

Портал — тонкая прослойка между пользователем и Open WebUI. Он не хранит
чаты и пароли: аккаунт создаётся в Open WebUI через админский API, поэтому
человек сразу попадает в тот же чат, память и пресеты. Своё портал хранит
только личные настройки.

```
браузер → nginx /portal/ → omni-portal → Open WebUI API
                                │
                                └→ portal.db (город, Telegram ID, PAT, пресет)
```

## Адреса

| Страница | Что делает |
|---|---|
| `/register` → `/portal/register` | создание аккаунта по инвайт-токену |
| `/portal/login` | вход по логину и паролю, открывает чат авторизованным |
| `/portal/account` | город, Telegram ID, GitHub-токен, пресет по умолчанию |
| `/portal/logout` | выход из портала |

## Пароль администратора

```
/srv/omnisecretary/secrets/webui-owner.txt   # EMAIL=admin, PASSWORD=...
```

```bash
make owner-creds    # показать логин и пароль
```

Файл создаётся при установке, права 600, в git не попадает. Сменить пароль —
Settings → Account в Open WebUI (портал пароль не хранит и не меняет).

## Регистрация

Публичная регистрация Open WebUI выключена. Новый аккаунт появляется только
через портал:

1. Логин: 3–32 символа, латиница, цифры, `.`, `-`, `_`. Зарезервированы
   `admin`, `owner`, `root`, `system`, `administrator`.
2. Пароль: минимум 8 символов, вводится дважды.
3. Токен приглашения: `REGISTER_TOKEN` из `.env`. Если он пуст —
   используется `TELEGRAM_CONFIRM_CODE` (16 символов, тот же, что у бота).

Ограничения: 5 регистраций с одного IP в час; повторный логин отклоняется
сообщением «Логин уже занят».

Внутри Open WebUI логин хранится как `<логин>@omnisecretary.local` — это
техническая деталь: Open WebUI требует почтовый формат, а почтового сервиса
нет. Портал подставляет адрес сам, пользователь всегда вводит только логин.

## Вход

`/portal/login` принимает логин и пароль, проверяет их через
`POST /api/v1/auths/signin` и кладёт выданный Open WebUI токен в
`localStorage` (портал и чат — один origin). Дальше редирект на `/`, и
пользователь уже авторизован. Пароль нигде не сохраняется.

Если аккаунт создан в обход портала (например, администратором), профиль
создастся автоматически при первом входе.

## Личные настройки

| Поле | Куда попадает |
|---|---|
| Город | `portal.db`; при указанном Telegram ID ещё и в `bot.db` — `/weather` и брифинг берут оттуда |
| Telegram ID | связка аккаунта с ботом |
| GitHub-токен | `portal.db`, только для личных задач (см. ограничение ниже) |
| Пресет | подсказка, какой пресет использовать по умолчанию |

Ограничение: MCP GitHub сейчас работает с общим PAT из `.env`
(`GITHUB_TOKEN`). Раздельные токены по пользователям требуют доработки
MCP-сервера — запланировано в `docs/plan.md`. Пока личный токен хранится,
но автоматически не применяется; не вводите туда токен с широкими правами.

## Безопасность

- `PORTAL_SECRET` подписывает cookie сессии (HMAC-SHA256), срок 7 дней,
  `HttpOnly`, `SameSite=Lax`.
- CSRF-токен в каждой форме, привязан к часу.
- Инвайт-токен сравнивается побайтно и не логируется.
- Пароли не хранятся порталом: хеширование и проверка — в Open WebUI.
- `portal.db` — права 600, лежит в `${DATA_ROOT}/portal/`.

## Диагностика

| Симптом | Причина |
|---|---|
| 502 на `/portal/` | контейнер `omni-portal` не запущен: `make portal-logs` |
| «Неверный токен приглашения» | `REGISTER_TOKEN` и `TELEGRAM_CONFIRM_CODE` не совпадают с введённым |
| «Логин уже занят» | такой пользователь есть в Open WebUI |
| Вход не открывает чат | проверьте, что открываете тот же домен (localStorage привязан к origin) |
| Настройки не применились к боту | укажите Telegram ID и сохраните ещё раз; бот читает `bot.db` |

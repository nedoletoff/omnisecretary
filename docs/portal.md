# Портал: регистрация, вход и личные настройки

Портал — небольшой сервис (FastAPI, 96 МБ, контейнер `omni-portal`),
который закрывает то, чего нет в Open WebUI v0.13.3 из коробки: регистрация
по токену без почтового сервера, вход по логину и хранение личных настроек.

Доступен на `https://nedoletoff.sknt.ru` (и на `https://nedoletoff.mooo.com`
для быстрого доступа):

| Адрес | Что делает |
|---|---|
| `/portal/login` | вход по логину и паролю (создаёт сессию Open WebUI) |
| `/portal/register` | регистрация: логин + пароль + токен приглашения |
| `/portal/account` | личные настройки вошедшего пользователя |
| `/portal/admin/status` | панель устройства (только владелец) |
| `/portal/quick` | календарь и заметки (быстрый доступ) |
| `/register` | короткий адрес регистрации |
| `/login`, `/signin` | короткие адреса входа → `/portal/login` |
| `/` | чат только при наличии cookie портала, иначе `/portal/login` |

Экран входа и регистрации — фирменный: Gruvbox-оформление, логотип,
подсказки по возможностям, кнопка показа пароля и отдельная кнопка
«Зарегистрироваться». Родной экран Open WebUI не подменяется (лицензия
Open WebUI запрещает менять брендинг), вместо этого неавторизованный
запрос к корню перенаправляется на портал.

## Регистрация по токену

1. Откройте `/register` (кнопка «Зарегистрироваться» есть и на экране входа).
2. Введите логин (латиница, цифры, `.`, `_`, `-`), пароль дважды и
   **токен приглашения**. Пароль можно показать кнопкой «Показать».
3. Аккаунт создаётся в Open WebUI с ролью `user`; портал сразу выполняет вход
   и открывает `/portal/account`, где пользователь добавляет GitHub-токен,
   город для погоды, Telegram ID и пресет.

**Токен приглашения** — 16 символов: `.env` → `TELEGRAM_CONFIRM_CODE` или
`secrets/telegram-confirm-code.txt`. Переменная `REGISTER_TOKEN` задаёт
отдельный токен; если она не задана, используется токен бота.

Почты нет: логин хранится как есть (без `@omnisecretary.local`).
Защита от перебора — таймауты после неудачных попыток.

## Вход

`/portal/login` проверяет пароль через `/api/v1/auths/signin` Open WebUI и,
при успехе, устанавливает cookie сессии. Можно заходить логином
(`nedoletoff`, `tg123…`) — портал подбирает формат автоматически. Поле
называется «Логин», а не «Email»; введённый пароль можно показать кнопкой
«Показать». Ниже формы — отдельная кнопка «Зарегистрироваться».

Пароли портал не хранит. Аутентификация — на стороне Open WebUI.

## Личные настройки

`/portal/account` (нужен вход): Telegram ID, город для погоды, GitHub-токен,
пресет по умолчанию и др.

- Город геокодируется и сохраняется в `bot.db`, чтобы `/weather` и брифинг
  использовали личную локацию.
- GitHub-токен сохраняется зашифрованным (ключ в `secrets/`), права файла
  БД ограничены. Отдельные права по пользователям для MCP — в плане.
- Данные хранятся в `${DATA_ROOT}/portal/portal.db`.

## Персональный Obsidian-вольт (API)

Портал предоставляет API для личного вольта каждого пользователя
(используется Android-приложением):

| Эндпоинт | Назначение |
|---|---|
| `GET/POST /api/m/vault/config` | подключение репозитория, ветка, PAT, push |
| `GET/POST /api/m/vault/permissions` | правила доступа по папкам |
| `POST /api/m/vault/sync` | синхронизация (pull/index/push) |
| `GET /api/m/vault/files` | список файлов (с учётом прав) |
| `GET /api/m/vault/read` | чтение заметки |
| `GET /api/m/vault/search` | поиск (FTS5) |
| `POST /api/m/vault/note` | создание/запись заметки в разрешённой папке |

**Безопасность вольта:**
- Токен шифруется на сервере, не возвращается клиенту в открытом виде.
- Права (read/list/search/create/append/update/delete) проверяются
  программно при каждом действии; при отсутствии разрешающего правила —
  отказ. Применяется самое точное правило по префиксу.
- Клон/индекс изолированы по пользователю (`${DATA_ROOT}/vaults/<id>`).

## Мобильный API

Портал также обслуживает `/api/m/*` для Android-клиента: сводка дня,
статус устройства, голос (STT/TTS), события календаря, задачи Vikunja,
заметки Open WebUI, напоминания, запись в вольт. Запросы выполняются от
имени авторизованного пользователя (Bearer/JWT), данные изолированы.

## Админ-панель устройства

`/portal/admin/status` — только владелец. Показывает температуру, нагрузку,
память/swap, диски, контейнеры, сертификат, бэкапы, VPN, UFW. Метрики
собираются скриптом в файл, docker-socket в портал не монтируется.

## Где хранятся доступы

| Что | Где |
|---|---|
| Логин/пароль владельца | `secrets/webui-owner.txt` (`make owner-creds`) |
| Токен приглашения | `.env` (`TELEGRAM_CONFIRM_CODE`) и `secrets/telegram-confirm-code.txt` |
| Личные настройки/вольты | `${DATA_ROOT}/portal/portal.db` (600) |
| Клоны вольтов пользователей | `${DATA_ROOT}/vaults/<user_id>` |
| Секрет подписи cookie | `.env` (`PORTAL_SECRET`) |
| База бота (локации, напоминания) | `${DATA_ROOT}/bot/bot.db` (600) |

## Управление

```bash
make portal-up | portal-down | portal-restart | portal-logs
make owner-creds
```

## Изоляция

- Регистрация создаёт обычного пользователя (`user`), не администратора.
- Сессия подписана HMAC (`PORTAL_SECRET`), формы защищены CSRF, пароли не
  логируются.
- Действия с календарём/заметками/вольтом выполняются с токеном
  пользователя — чужие данные недоступны.
- Права вольта — серверное ограничение, не зависящее от промпта.

## Ограничения

- Нет восстановления пароля по почте (почтового сервиса нет): сброс —
  через администратора в Open WebUI.
- MCP-инструменты вольта в веб-чате ещё не полностью переведены на
  per-user контекст (приложение и `/api/m/vault/*` — да).
- Панель статуса читает файл метрик; при сбое сбора данные могут быть
  устаревшими.

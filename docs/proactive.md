# Проактивность и мобильный доступ

## Утренний брифинг

Отдельный контейнер `proactive` (профиль `proactive`, 96 МБ) раз в сутки
собирает сводку и отправляет её в Telegram владельцу.

### Настройка из бота

```
/briefing                  показать текущие настройки
/briefing 08:00            время отправки (часовой пояс — TZ)
/briefing sections weather,calendar,tasks,notes
/briefing off              выключить; /briefing on — включить
```

Настройки хранятся в `${DATA_ROOT}/bot/briefing.json` (600) и важнее
`BRIEFING_TIME` из `.env`. Менять может только владелец
(`TELEGRAM_OWNER_ID`). Разделы можно комбинировать в любом порядке.

```
07:30 (BRIEFING_TZ)
   ├── погода       api.met.no (без ключа)
   ├── календарь    Open WebUI /api/v1/calendars/events
   ├── задачи       Vikunja /api/v1/tasks?filter=done=false
   └── заметки      количество файлов в AI/Inbox вольта
        │
        ▼
   Telegram sendMessage → TELEGRAM_OWNER_ID
```

Пример сообщения:

```
Доброе утро. 11.11.2026, 07:30.

Погода (Москва): сейчас +3 °C, облачно; за 12 ч от +1 до +3 °C, осадки 0.0 мм.

Календарь: на сегодня событий нет.

Задачи:
Просрочено:
— Оплатить хостинг (просрочено 09.11)
Сегодня:
— Позвонить в сервис

Заметки: в AI/Inbox 4 шт., последняя — 2026-11-10-идея.md.
```

### Запуск

```bash
make proactive-up
make briefing        # собрать текст сейчас, без отправки
make briefing-send   # собрать и отправить в Telegram
make proactive-logs
```

### Настройки (`.env`)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `BRIEFING_TIME` | `07:30` | время отправки, `ЧЧ:ММ` |
| `TZ` | `Europe/Moscow` | часовой пояс расписания |
| `WEATHER_LAT`, `WEATHER_LON` | Санкт-Петербург, Ломоносовская | координаты по умолчанию |
| `WEATHER_CITY` | `Санкт-Петербург, Ломоносовская` | подпись в сообщении |
| `WEBUI_API_KEY` | — | ключ владельца для чтения календаря |
| `VIKUNJA_API_TOKEN` | — | чтение задач |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_OWNER_ID` | — | куда отправлять |

Локация владельца берётся из `bot.db` (команда `/weather <город>` в боте),
если она задана; иначе — из `WEATHER_*`. У остальных пользователей локация
своя и на брифинг не влияет.

Без Telegram-токена брифинг собирается, но не отправляется: `make briefing`
покажет текст. Состояние «за сегодня отправлено» хранится в
`${DATA_ROOT}/volumes/proactive/last-briefing` — повторной отправки не будет.

### Почему met.no, а не open-meteo

`api.open-meteo.com` и `alphacephei.com` недоступны из сети Pi (таймаут на
уровне маршрута), а `api.met.no` отвечает за 0,2 с. Ключ не нужен, требуется
только `User-Agent`. См. ADR-029.

### Ограничения

- Брифинг отправляется один раз в сутки; если Pi был выключен в 07:30,
  отправка не «догоняется». Догон — в этапе 7.
- Напоминания по расписанию (кроме брифинга) пока не реализованы:
  планируются как команда `/remind` в Telegram-боте + таблица в PostgreSQL.
- Погода — только текущая и на 12 часов, без почасового прогноза.

## PWA и мобильный доступ

Open WebUI v0.13.3 отдаёт `manifest.json` (проверяется smoke-тестом) и
работает как PWA — отдельный клиент не нужен.

### Установка на телефон

1. Открыть `http://<pi-ip>/` в Chrome (Android) или Safari (iOS).
2. «Добавить на главный экран» / «Установить приложение».
3. Войти тем же аккаунтом — чаты, пресеты и память те же, что в вебе.

### Быстрый доступ к пресетам

- Пресеты — это модели в селекторе: после установки PWA они в одном тапе
  от нового чата.
- Ярлык на главном экране открывает последний чат; для «быстрого действия»
  создайте отдельный ярлык браузера на `http://<pi-ip>/` и выбирайте пресет
  в списке моделей.
- Временный/приватный чат — меню чата → Temporary Chat (в PWA доступно так же).

### Внешний доступ

PWA требует HTTPS для установки вне localhost. Варианты:

- **LAN**: установка работает по HTTP в некоторых браузерах, но надёжнее
  HTTPS (см. `nginx/` и `docs/security.md`, Cloudflare Tunnel).
- **Cloudflare Tunnel**: `cloudflared` уже установлен на Pi; токен туннеля —
  секрет, настраивается вручную.

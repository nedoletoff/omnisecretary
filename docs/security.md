# Безопасность

## Модель

Сервис личный/self-hosted. Основные риски: утечка секретов, несанкционированный
доступ (веб/Telegram/API), компрометация через инструменты (shell/GitHub/файлы),
утечка данных между пользователями, перехват трафика.

## Секреты и доступы

- **Хранение:** `.env` и `secrets/` (права 600, каталоги 700), не в git.
  `.env.example` — только плейсхолдеры. Содержимое `.env` не выводится в чат/логи.
- **Токены:** GitHub PAT, Telegram, API-ключи LLM, `PORTAL_SECRET`, VPN-ключи —
  только в защищённых файлах/переменных. PAT вольтов пользователей шифруются
  в БД портала; GitHub-токен в настройках — зашифрован.
- **Ротация:** при подозрении на утечку — перевыпуск токенов, смена паролей,
  проверка истории git и логов.
- **Права PAT (GitHub):** минимальные, только нужные репозитории (Contents
  read/write при необходимости, Issues/PR — по задаче), без Administration/Secrets.

## Аутентификация и изоляция пользователей

- Публичная регистрация Open WebUI отключена. Регистрация — по токену через
  портал; вход — по логину/паролю.
- Telegram — allowlist и/или код подтверждения; привязка к аккаунтам.
- Роли: владелец (admin) и пользователи; админ-функции (статус, настройки
  серверного вольта) — только владельцу.
- Данные (чаты, заметки, задачи, календарь, настройки, вольты) изолированы по
  аккаунту. Запросы мобильного API выполняются от имени пользователя.

## Сеть и транспорт

- HTTPS (Let's Encrypt), редирект HTTP→HTTPS, HSTS (по конфигурации nginx).
- Nginx — единая точка входа; БД и внутренние сервисы не публикуются наружу.
  Qdrant — при необходимости только `127.0.0.1`.
- UFW: 80/443/22 по политике, 8081 ограничен LAN (где настроено).
- VPN-прокси используется только для нужных исходящих соединений; локальные
  сервисы исключены (`NO_PROXY`).

## Контейнеры и хост

- Docker **rootless**, лимиты памяти/CPU, `no-new-privileges`, разделение
  сетей (frontend/backend/mcp).
- Без публикации Docker socket в сервисы приложения.
- Rootful демон отключён после миграции; откат контролируемый.
- Опасные операции на хосте (sudo, apt, systemctl, fstab, форматирование
  дисков) — вручную, с подтверждением. Скрипты — идемпотентные.

## Obsidian-вольт и права доступа

- Персональные вольты: отдельный клон/индекс на пользователя, токен
  зашифрован, репозитории приватные.
- **Права по папкам** (read/list/search/create/append/update/delete)
  задаются пользователем и проверяются **программно на сервере** при
  каждом действии (чтение, список, поиск, запись). Отсутствие разрешения
  → отказ. Модель/клиент не могут расширить доступ.
- Запись — только по прямой команде, в разрешённые пути; коммит/push по
  настройке. Фоновых записей нет.
- Серверный вольт владельца: форма `/vault/` под Basic Auth, токен в
  `secrets/`.

## MCP и инструменты

- Внешние MCP-серверы, минимальные права на пресет, изоляция сетей.
- **Sandbox:** без docker.sock/privileged/host-сети, ограниченный набор
  команд и каталог `/workspace`, без доступа к БД/MCP с секретами по
  выделенной сети.
- **GitHub MCP:** операции записи могут быть ограничены флагами/политикой;
  токен — минимальных прав.
- Инструменты с shell/доступом к репозиториям — с подтверждениями в UX
  где применимо.

## Android-приложение

- Трафик только HTTPS, адрес сервера настраивается.
- Токен сессии — `EncryptedSharedPreferences`; биометрическая блокировка —
  опционально.
- Приватный чат: временный, `FLAG_SECURE` (защита экрана).
- Секреты не встраиваются в APK. Локальные очереди хранят только данные,
  необходимые для отправки действий пользователя.
- Разрешения: сеть, микрофон, камера, уведомления/будильники — по функциям.

## Портал и API

- Cookie сессии подписаны (`PORTAL_SECRET`, fail-fast при слабом/пустом),
  CSRF/Origin-проверки где применимо, таймауты/ограничения попыток вместо
  жёстких блокировок в неподходящих сценариях.
- `/api/m/*` требует авторизацию; операции выполняются в контексте
  пользователя.

## Бэкапы и восстановление

- Бэкапы PostgreSQL и Qdrant, метаданные; файлы с ограниченными правами.
- `.env` и `secrets/` — хранить отдельно и безопасно (не в публичных местах).

## Обновления

- Образы с фиксированными тегами; обновление — осознанный коммит после
  проверки. Зависимости Android/CI обновляются с контролем сборки.
- Рекомендуется периодически проверять advisories (образы, Python, npm/Gradle).

## Ограничения / открытые вопросы

- MCP-вольт в веб-чате не полностью per-user (изоляция в приложении и
  `/api/m/vault/*` реализована).
- Полная оценка безопасности мобильного клиента требует тестирования на
  устройствах и ревью перед широким распространением.
- Автоматический аудит зависимостей в CI — желательное улучшение.

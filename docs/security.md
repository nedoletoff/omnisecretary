# Безопасность

## Модель угроз (кратко)

| Угроза | Защита |
|---|---|
| Случайная публикация секретов | `.env` в `.gitignore`, только `.env.example` |
| Доступ из LAN без пароля | `WEBUI_AUTH=true`, регистрация закрыта |
| Открытый Telegram-бот | allowlist ID, long polling, отказ посторонним |
| Утечка БД наружу | Postgres/Qdrant/Redis не публикуют порты |
| Вредоносные действия инструментов | подтверждения, минимальные права, изоляция контейнеров |
| Кража PAT GitHub | fine-grained PAT, минимум прав, только env |
| Подмена трафика в LAN | HTTPS/Cloudflare Tunnel при выходе за LAN |

## Секреты

Хранятся **только** в `.env` (права 600) и в env контейнеров.

| Переменная | Назначение | Генерация |
|---|---|---|
| `POSTGRES_PASSWORD` | пароль БД | `openssl rand -hex 24` |
| `WEBUI_SECRET_KEY` | подпись сессий Open WebUI | `openssl rand -hex 32` |
| `QDRANT_API_KEY` | доступ к Qdrant | `openssl rand -hex 24` |
| `VIKUNJA_SECRET` | подпись сессий Vikunja | `openssl rand -hex 32` |
| `VIKUNJA_ADMIN_PASSWORD` | пароль первого пользователя Vikunja (необязательно) | `openssl rand -hex 16` |
| `OPENAI_API_KEY` | облачная LLM | из личного кабинета провайдера |
| `EMBEDDING_API_KEY` | эмбеддинги | из личного кабинета провайдера |
| `TELEGRAM_BOT_TOKEN` | бот | @BotFather |
| `GITHUB_TOKEN` | GitHub MCP | GitHub → Developer settings → Fine-grained tokens |
| `VIKUNJA_API_TOKEN` | задачи из чата | `make vikunja-admin` (или Настройки → API-токены) |
| `VAULT_ADMIN_PASSWORD` | форма `/vault/` | `openssl rand -hex 16` (bootstrap) |
| `REDIS_PASSWORD` | Redis (веб-сокеты, кэш) | `openssl rand -hex 24` (bootstrap) |
| `PORTAL_SECRET` | подпись cookie портала | `openssl rand -hex 32` (bootstrap) |
| `TELEGRAM_CONFIRM_CODE` | код доступа к боту и регистрации | `openssl rand -hex 8` (bootstrap) |

Правила:
- Пароль Postgres — hex: попадает в `DATABASE_URL`, спецсимволы ломают URL.
- Учётные данные владельца: `/srv/omnisecretary/secrets/webui-owner.txt`
  (логин `admin`, пароль рядом; `make owner-creds`). Почта не используется —
  вход по логину.
- `.env` не бэкапится автоматически и не покидает Pi.
- Пароль пользователя Vikunja, созданный `make vikunja-admin`, лежит в
  `${DATA_ROOT}/secrets/vikunja-admin.txt` (права 600). Сменить в интерфейсе
  и удалить файл. Каталог `secrets/` в git не попадает.
- При компрометации: заменить значение, `make restart`, при необходимости
  сменить пароль пользователя в Open WebUI.
- `docker inspect` показывает env контейнера — доступ к Docker API равен
  доступу к секретам. Не давать группу `docker` недоверенным пользователям.
- Токен Obsidian-вольта — `${DATA_ROOT}/secrets/vault-git-token` (600),
  каталог монтируется только в `vault-manager` и `mcp-vault` (read-only).
  В `.git/config` и в URL репозитория токен не хранится.
- Токен Vikunja — `${DATA_ROOT}/secrets/vikunja-api-token.txt` (600) и `.env`.
- `secrets/` не попадает в git и в бэкапы; восстанавливается вручную.

## Сетевая экспозиция

```
Интернет ──(Cloudflare Tunnel)──▶ 127.0.0.1:80 ──▶ nginx ──▶ open-webui
LAN ─────────────────────────────▶ :80/:443
```

- Наружу открыт только nginx (80/443). Postgres, Redis, Open WebUI — нет.
- Vikunja доступна через nginx на `:8081` — только LAN, на роутере не
  пробрасывать. Регистрация в Vikunja закрыта, вход по логину и паролю.
- Qdrant слушает `127.0.0.1:6333` и требует `api-key`.
- UFW: разрешить 22, 80, 443; 8081 — только из `192.168.0.0/24`.
  Скрипт: `sudo ./scripts/harden-host.sh`.
- HTTP (`:80`) для внешнего домена отвечает **301 на HTTPS**; исключения —
  ACME-челлендж и `/healthz` для мониторинга. HSTS отдаётся на всех ответах.
- Внутренние сети Docker разделены: `frontend` (nginx), `backend`
  (база, Redis, Qdrant, песочница) и `mcp` (MCP-серверы + Open WebUI).
  Песочница **не видит** MCP-серверы, поэтому prompt injection из shell
  не дотянется до GitHub-токена и вольта.
- Не публиковать порт 3000 (Open WebUI) в интернет даже для отладки.

## Таймауты на ввод паролей и кодов

Не лимиты запросов, а паузы после серии ошибок:

| Где | Порог | Пауза | Ключ |
|---|---|---|---|
| Портал, вход | 5 ошибок за 15 мин | 15 мин | IP + логин |
| Портал, регистрация | 5 ошибок за 15 мин | 15 мин | IP |
| Бот, код подтверждения | 5 ошибок | 10 мин | Telegram ID |

IP берётся из `X-Real-IP`, который ставит nginx: подставить чужой нельзя.
Успешный вход/регистрация сбрасывают счётчик. Пароли сравниваются в
постоянное время (`hmac.compare_digest`).

## Права на файлы с личными данными

| Путь | Права | Почему |
|---|---|---|
| `.env` | 600 | все секреты |
| `secrets/` | 700, файлы 600 | токены, пароли |
| `portal/portal.db` | 700/600 | GitHub-токены, ID пользователей |
| `bot/bot.db` | 700/600 | ID Telegram, города |
| `backups/` | 700, файлы 600 | дампы всей переписки и памяти |

`umask 077` в `backup.sh` и `chmod` в `bootstrap-pi.sh` держат это
автоматически. Контейнеры получают только `CAP_DAC_OVERRIDE` — остальные
root-возможности сброшены (`cap_drop: [ALL]`), у песочницы дополнительно
`pids_limit`, `cpus` и `tmpfs /tmp`.

## Аутентификация и роли

- `ENABLE_SIGNUP=false` — самостоятельная регистрация в Open WebUI запрещена;
  новые аккаунты создаются только через портал по токену приглашения.
- `CORS_ALLOW_ORIGIN` — только свой домен и LAN, без `*` (разделитель `;`).
- `JWT_EXPIRES_IN=2592000` — токен живёт 30 дней, а не бессрочно.
- Первый пользователь создаётся при первом входе и становится администратором.
- Дальше пользователей создаёт админ вручную.
- Роли Open WebUI: `admin`, `user`, `pending`.
- `DEFAULT_USER_ROLE=user`; для гостевого доступа — отдельный аккаунт с
  ограниченными моделями и без доступа к инструментам.

## Telegram (этап 3)

- Бот работает через long polling: публичный webhook и открытый порт не нужны.
- `TELEGRAM_ALLOWED_IDS` — список числовых ID; всё остальное игнорируется.
- Каждая попытка постороннего логируется (ID, username, время).
- Токен бота — только в `.env`; при утечке — `/revoke` у @BotFather.
- Групповые чаты не поддерживаются (только личные).

## MCP-инструменты

- MCP-серверы — отдельные контейнеры в сети `backend`, порты не публикуются.
- Tool servers зарегистрированы **без `access_grants`** → видны только
  администратору. Обычные пользователи инструментов не получают.
- Пресеты получают только нужные серверы (`meta.toolIds`): Private — ничего,
  Secretary — задачи и файлы, Coder — GitHub и песочница.
- `mcp-sandbox` не имеет docker.sock, host-сети и `privileged`; работает
  только в `${DATA_ROOT}/sandbox`; команды `sudo/apt/systemctl/rm/dd/mount`
  запрещены, метасимволы оболочки (`; | & > <`) отклоняются.
- Опасные операции на самом хосте (`sudo`, `apt`, `systemctl`, `/etc/fstab`,
  форматирование дисков) **не автоматизированы** — только вручную владельцем.
- Вольт: запись только в `AI/`, каждая запись — коммит; чужие папки
  недоступны для записи (проверка на сервере, не только в промпте).

## GitHub PAT

- Только **fine-grained** PAT, не classic.
- Область: выбранные репозитории (не «All repositories»).
- Права: `Contents: read/write`, `Issues: read/write`, `Pull requests: read/write`.
  Никаких `Administration`, `Secrets`, `Workflows`, если не нужны явно.
- Срок жизни — 90 дней, с напоминанием о ротации.
- PAT передаётся MCP-контейнеру через env, не через файл в репозитории.

## Подтверждения опасных операций (этап 4)

Опасные инструменты (SSH/Computer Use, запись файлов вне вольта,
git push, удаление) обязаны требовать подтверждения:

| Операция | Политика |
|---|---|
| `ls`, `cat`, `df`, чтение логов | без подтверждения |
| запись/правка файлов в вольте | без подтверждения (git-история) |
| `rm`, `mv` вне вольта | подтверждение |
| `sudo`, `apt`, `systemctl` | подтверждение + запрет в промпте |
| `git push` в чужие репозитории | подтверждение |
| SSH на другие хосты | allowlist хостов + подтверждение |

Технически: SSH-MCP в этой версии не разворачивается. Вместо него —
`mcp-sandbox` (изолированный контейнер, allowlist команд) и ручные
операции владельца на хосте. Полноценный SSH/Computer Use — отдельный этап
с выделенным ключом, allowlist хостов и подтверждением в интерфейсе.

## Проактивность

- `TELEGRAM_BOT_TOKEN` и `WEBUI_API_KEY` передаются только в env контейнера
  `proactive`, в репозиторий не попадают.
- Брифинг уходит единственному получателю — `TELEGRAM_OWNER_ID`.
- Вольт монтируется в `proactive` только на чтение.

## Голос

- STT и TTS — отдельные контейнеры без публикации портов, только `backend`.
- Аудио не сохраняется: STT обрабатывает запрос в памяти и удаляет временный
  файл; TTS ничего не пишет на диск.
- Модели скачиваются при сборке, в git не попадают.
- `mem_limit` защищает от OOM: STT 320 МБ, TTS 640 МБ (Piper 192 МБ).

## Контейнеры

- `no-new-privileges:true` у всех сервисов.
- Нет `privileged: true`, нет монтирования `docker.sock`.
- Лимиты памяти и ротация логов — защита от исчерпания ресурсов.
- Образы с фиксированными тегами; обновление — осознанное действие.

## TLS

- LAN: допустим HTTP внутри доверенной сети.
- Выход в интернет: Cloudflare Tunnel (TLS на стороне Cloudflare) либо
  Let's Encrypt + HSTS (см. `nginx/conf.d/10-ssl.conf.example`).
- Приватный ключ — только в `nginx/certs/` (в `.gitignore`), права 600.

## Что делать при инциденте

1. `make down` — остановить стек.
2. Отозвать скомпрометированные токены (LLM, Telegram, GitHub).
3. Сменить `POSTGRES_PASSWORD`, `WEBUI_SECRET_KEY`, `QDRANT_API_KEY` в `.env`.
4. Проверить логи nginx (`make logs`) на подозрительные запросы.
5. Восстановить данные из бэкапа при необходимости.
6. Ротировать пароль администратора Open WebUI.

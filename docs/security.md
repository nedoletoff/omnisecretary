# Безопасность

## Модель угроз (кратко)

| Угроза | Защита |
|---|---|
| Случайная публикация секретов | `.env` в `.gitignore`, только `.env.example` |
| Доступ из LAN без пароля | `WEBUI_AUTH=true`, регистрация закрыта |
| Открытый Telegram-бот | allowlist ID, long polling, отказ посторонним |
| Утечка БД наружу | Postgres/Qdrant/Redis не публикуют порты |
| Вредоносные действия инструментов | подтверждения, минимальные права, изоляция контейнеров |
| Кража PAT GitHub | fine-grained PAT, минимум прав, только env |
| Подмена трафика в LAN | HTTPS/Cloudflare Tunnel при выходе за LAN |

## Секреты

Хранятся **только** в `.env` (права 600) и в env контейнеров.

| Переменная | Назначение | Генерация |
|---|---|---|
| `POSTGRES_PASSWORD` | пароль БД | `openssl rand -hex 24` |
| `WEBUI_SECRET_KEY` | подпись сессий Open WebUI | `openssl rand -hex 32` |
| `QDRANT_API_KEY` | доступ к Qdrant | `openssl rand -hex 24` |
| `OPENAI_API_KEY` | облачная LLM | из личного кабинета провайдера |
| `EMBEDDING_API_KEY` | эмбеддинги | из личного кабинета провайдера |
| `TELEGRAM_BOT_TOKEN` | бот (этап 3) | @BotFather |
| `GITHUB_PAT` | GitHub MCP (этап 4) | GitHub → Developer settings |

Правила:
- Пароль Postgres — hex: попадает в `DATABASE_URL`, спецсимволы ломают URL.
- `.env` не бэкапится автоматически и не покидает Pi.
- При компрометации: заменить значение, `make restart`, при необходимости
  сменить пароль пользователя в Open WebUI.
- `docker inspect` показывает env контейнера — доступ к Docker API равен
  доступу к секретам. Не давать группу `docker` недоверенным пользователям.

## Сетевая экспозиция

```
Интернет ──(Cloudflare Tunnel)──▶ 127.0.0.1:80 ──▶ nginx ──▶ open-webui
LAN ─────────────────────────────▶ :80/:443
```

- Наружу открыт только nginx (80/443). Postgres, Redis, Open WebUI — нет.
- Qdrant слушает `127.0.0.1:6333` и требует `api-key`.
- UFW (рекомендуется): разрешить 22, 80, 443; остальное закрыть.
- Не публиковать порт 3000 (Open WebUI) в интернет даже для отладки.

## Аутентификация и роли

- `ENABLE_SIGNUP=false` — самостоятельная регистрация запрещена.
- Первый пользователь создаётся при первом входе и становится администратором.
- Дальше пользователей создаёт админ вручную.
- Роли Open WebUI: `admin`, `user`, `pending`.
- `DEFAULT_USER_ROLE=user`; для гостевого доступа — отдельный аккаунт с
  ограниченными моделями и без доступа к инструментам.

## Telegram (этап 3)

- Бот работает через long polling: публичный webhook и открытый порт не нужны.
- `TELEGRAM_ALLOWED_IDS` — список числовых ID; всё остальное игнорируется.
- Каждая попытка постороннего логируется (ID, username, время).
- Токен бота — только в `.env`; при утечке — `/revoke` у @BotFather.
- Групповые чаты не поддерживаются (только личные).

## GitHub PAT (этап 4)

- Только **fine-grained** PAT, не classic.
- Область: выбранные репозитории (не «All repositories»).
- Права: `Contents: read/write`, `Issues: read/write`, `Pull requests: read/write`.
  Никаких `Administration`, `Secrets`, `Workflows`, если не нужны явно.
- Срок жизни — 90 дней, с напоминанием о ротации.
- PAT передаётся MCP-контейнеру через env, не через файл в репозитории.

## Подтверждения опасных операций (этап 4)

Опасные инструменты (SSH/Computer Use, запись файлов вне вольта,
git push, удаление) обязаны требовать подтверждения:

| Операция | Политика |
|---|---|
| `ls`, `cat`, `df`, чтение логов | без подтверждения |
| запись/правка файлов в вольте | без подтверждения (git-история) |
| `rm`, `mv` вне вольта | подтверждение |
| `sudo`, `apt`, `systemctl` | подтверждение + запрет в промпте |
| `git push` в чужие репозитории | подтверждение |
| SSH на другие хосты | allowlist хостов + подтверждение |

Технически: MCP-сервер SSH работает в контейнере с непривилегированным
пользователем, без доступа к docker.sock и без ключей кроме выделенного.

## Контейнеры

- `no-new-privileges:true` у всех сервисов.
- Нет `privileged: true`, нет монтирования `docker.sock`.
- Лимиты памяти и ротация логов — защита от исчерпания ресурсов.
- Образы с фиксированными тегами; обновление — осознанное действие.

## TLS

- LAN: допустим HTTP внутри доверенной сети.
- Выход в интернет: Cloudflare Tunnel (TLS на стороне Cloudflare) либо
  Let's Encrypt + HSTS (см. `nginx/conf.d/10-ssl.conf.example`).
- Приватный ключ — только в `nginx/certs/` (в `.gitignore`), права 600.

## Что делать при инциденте

1. `make down` — остановить стек.
2. Отозвать скомпрометированные токены (LLM, Telegram, GitHub).
3. Сменить `POSTGRES_PASSWORD`, `WEBUI_SECRET_KEY`, `QDRANT_API_KEY` в `.env`.
4. Проверить логи nginx (`make logs`) на подозрительные запросы.
5. Восстановить данные из бэкапа при необходимости.
6. Ротировать пароль администратора Open WebUI.

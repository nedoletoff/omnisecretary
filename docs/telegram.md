# Telegram-бот

Второе окно к тому же бэкенду Open WebUI. Бот не хранит переписку у себя:
сообщения пишутся в чаты Open WebUI, поэтому диалог, начатый в Telegram,
продолжается в вебе под тем же пользователем.

## Запуск

1. Получить токен у [@BotFather](https://t.me/BotFather) (`/newbot`).
2. Узнать свой Telegram user ID: написать [@userinfobot](https://t.me/userinfobot).
3. В `.env`:

```dotenv
TELEGRAM_BOT_TOKEN=123456:AA...
# Allowlist: только эти ID. Все остальные игнорируются и попадают в лог.
TELEGRAM_ALLOWED_IDS=111111111,222222222
# Ваш ID — бот работает под вашим аккаунтом Open WebUI (чаты общие с вебом).
TELEGRAM_OWNER_ID=111111111
# Необязательно: явное соответствие TG ID → email аккаунта Open WebUI.
# TELEGRAM_ACCOUNT_MAP=222222222:wife@omnisecretary.local
TELEGRAM_DEFAULT_MODEL=secretary
```

4. Запустить профиль:

```bash
make tg-up      # docker compose --profile telegram up -d
make tg-logs    # смотреть логи
```

## Изоляция пользователей

| Telegram ID | Аккаунт Open WebUI | Что видит |
|---|---|---|
| `TELEGRAM_OWNER_ID` | владелец (`secrets/webui-owner.txt`) | свои чаты из веба и Telegram |
| из `TELEGRAM_ACCOUNT_MAP` | указанный email | свои чаты этого аккаунта |
| остальные из allowlist | `tg<id>@omnisecretary.local` (создаётся автоматически) | только свои чаты |

Каждый аккаунт видит только свои чаты: список чатов и память в Open WebUI
привязаны к пользователю. Шаринг чатов и заметок выключен на уровне прав
(`make init-webui`). Пароли автоматически созданных аккаунтов лежат в
`${DATA_ROOT}/bot/bot.db` (права 600) — при необходимости владелец может
сбросить пароль в Admin Panel.

Публичная регистрация в Open WebUI закрыта (`ENABLE_SIGNUP=false`).
Доступ к боту — только allowlist или код подтверждения (ниже).

## Вход по коду подтверждения

Если нужно пустить человека, не вписывая его ID в `.env`:

```dotenv
TELEGRAM_OPEN_ACCESS=true
TELEGRAM_CONFIRM_CODE=<16 символов>
```

Новый пользователь пишет боту → получает «🔒 Это приватный ассистент.
Отправьте код подтверждения» → отправляет код → доступ открывается
навсегда (ID сохраняется в `bot.db`, таблица `allowed`).

Код генерируется при установке и лежит в
`${DATA_ROOT}/secrets/telegram-confirm-code.txt` (права 600). Не публикуйте
его: любой, кто знает код, получает свой изолированный аккаунт.

Владелец может посмотреть список допущенных: `/users`.

Чтобы закрыть открытый вход — `TELEGRAM_OPEN_ACCESS=false` и
`make tg-restart`; уже допущенные ID останутся в `bot.db`.

## Команды

| Команда | Действие |
|---|---|
| `/new [пресет]` | новый чат (secretary по умолчанию) |
| `/presets` | список пресетов |
| `/model <пресет>` | пресет для новых чатов |
| `/app` | открыть веб-интерфейс: Mini App при HTTPS, иначе браузер |
| `/users` | (владелец) кто допущен к боту |
| `/private` | приватный режим: ничего не сохраняется, история не читается |
| `/public` | вернуться к обычным чатам |
| `/remind 20:30 текст` | напоминание (`+15m`, `12.11 09:00`) |
| `/reminders` | активные напоминания |
| `/forget <id>` | удалить напоминание |
| `/help` | справка |

Приватный режим отправляет запрос без `chat_id`: Open WebUI не создаёт чат
и не пишет в память. Контекст живёт только в памяти процесса бота
(последние 6 пар сообщений) и исчезает при перезапуске.

## Mini App (тот же дизайн)

Команда `/app` присылает кнопку. Если `PUBLIC_URL` начинается с `https://`,
Telegram открывает веб-интерфейс внутри себя (Web App) — та же Gruvbox-тема,
те же чаты и пресеты, что в браузере. При `http://` открывается обычная
ссылка в браузере: Telegram требует HTTPS для Mini App.

HTTPS и проброс портов — [docs/router.md](router.md).

## Ограничения

- Бот работает по long polling — входящие порты не нужны.
- Бесплатная модель Pollinations: 1 ответ в 45 секунд на IP. Бот отвечает
  понятной ошибкой; для нормальной работы нужен платный провайдер.
- Голосовые сообщения пока не обрабатываются (этап 5, Vosk).
- Бот не поддерживает файлы и изображения — только текст.
